# Live check — M4.1 (игровой поток, тик 20 TPS)

Состояние: **не выполнялось**. В M4.1 сеть живым клиентом не проверялась —
ниже чек-лист владельцу; пункт «живой клиент входит как раньше» из §6
считается закрытым только после него. Автоматически проверено только
`cargo test --workspace` (тик, каналы, kick, реплей) и сухой запуск
сервера (слушает `0.0.0.0:25565`, шаблон мира не изменён).

## Шаги

1. Запустить сервер: `tools\run-server.bat` (или `cargo run -p server
   --release`). Ожидание: в логе есть `listening local=0.0.0.0:25565`,
   `WARN`/`ERROR` нет.
2. В Minecraft **26.3** → Multiplayer → Add Server: `localhost:25565`.
   Записать **время входа** (от «Join Server» до появления мира) и статус
   в списке (MOTD, версия, `0/20`).
3. Ходьба 30+ блоков; `F3+G`, чтобы видеть границы чанков. Проверить
   **дыры** (не отрисованные чанки) впереди и по бокам.
4. Скриншот (мир + F3) положить рядом с этим файлом или в
   `C:\MineRust-data\traces\`.
5. Открыть `logs\latest.log` клиента: строк с `WARN`/`ERROR` про наш
   сервер быть не должно (записать, если есть).
6. В логе сервера раз в 5 секунд идёт строка `INFO ... game tick
   ticks=<n> metrics=TickMetrics { ... }`; при остановке —
   `game thread stopped`. Записать **p50/p99/max длительности тика** из
   последней строки и **дрейф** (критерий §6: дрейф < 5 мс, p99 < 20 мс).

## Что записать в отчёт

  WARN/ERROR = ____; p50/p99/max = ____/____/____ мс; дрейф = ____ мс.

## Заметки

- Вход (join-последовательность) не менялся в M4.1: ждём те же пакеты,
  что и в M3.3.
- Реплей (необязательно): задать `MINERUST_REPLAY=<путь>\replay.jsonl`
  перед запуском; каждая применённая команда тика пишет одну строку.

## 2. Как сервер узнает, что игрок в воде (b)

Нужно уметь читать блок в точке (ноги ≈ y−0.1, глаза ≈ y+1.62) и решать
«в воде/под водой». Сегодня:

- **Чтение блока в тике недоступно:** `Region`/`Scheduler` владеют только
  игроками (`crates/net/src/game/region.rs`, `scheduler.rs`); блоки есть в
  `TemplateWorld`/`Arc<ReadyChunks>` (`crates/server/src/template.rs`,
  `crates/net/src/chunks.rs`), то есть в форме готовых wire-пейлоадов, а не как
  быстрый доступ «дай состояние блока по (x,y,z)».
- **Нужна общая основа с ломанием блока:** и плаванию (чтение), и ломанию
  (чтение+запись) нужен **блочный стор секций**. Предлагается ввести его
  один раз: `ChunkStore` — по ключу (измерение, chunk_x, chunk_z) держит
  секции с состояниями блоков (палитра/индексы) и светом, умеет
  `get_block(x,y,z)` и `set_block(x,y,z,state)` с пометкой dirty; из него же
  строятся wire-пейлоады (и он же нужен для инвалидации кеша из
  `docs/BLOCK-BREAKING.md` §3/стадия 1).
- **Стоимость.** Точных замеров нет (бенчмарка загрузки чанка/света нет —
  «не найдено»). Есть ориентиры: сборка батча ≈ 2.4 с
  (`crates/server/src/template.rs`), вход ≈ 109 мс/бота при стриме
  3348 чанков (`docs/BENCH-M4.md`), кеш входа снижал 6058–7747 мс → 3015–3022 мс
  (`docs/PROGRESS.md`). Кеш `ReadyChunks` уже индексирован O(1) по чанку
  (`crates/net/src/chunks.rs`), поэтому добавление «hot path: блок по позиции»
  — это в первую очередь вопрос хранения секций в читаемой форме, а не скорости
  сети.
- **Что мерить перед реализацией:** стоимость `get_block` на горячем пути
  (тик) и цену построения `ChunkStore` из шаблона один раз при старте.

## 3. Сценарии проверки (c)

Как оказаться в воде **без правки шаблона v3**:

1. **Dev-параметр стартовой позиции** в конфиге сервера (`spawn_override =
   (x,y,z)`) — тогда клиент входит сразу в воду. Требует правки сервера
   (в этом шаге запрещено — в план).
2. **Правка копии мира, а не шаблона:** `Prepare-RunWorld` уже копирует v3 в
   рабочий мир прогона; можно изменить `SpawnX/SpawnY/SpawnZ` в
   `<run>\world\level.dat` (копия), оставив v3 нетронутым. Нужен tiny-tool
   записи NBT (кодек в `crates/protocol` уже есть).
3. **Телепорт через сущность**: у нашего сервера нет команд/RCON, поэтому
   «игрок сам идёт в воду» (вход пешком/падение) — самый ручной, но честный путь.
4. Координаты воды известны из `docs/RUNBOOK-STEP8-TRACES.md`: столб у
   (105..107, −28..−32), вода y=37..41, рекомендуемая точка **(106, −31), y=41**,
   чанк (6,−2) — тот же, что спавн, значит входит в готовое окно R=10 (473 чанка).

**Риски:** клиент может утонуть/получить эффект, если стоять долго; вода в
шаблоне может быть «мелкой» для позы плавания (глубина до 5 блоков);
автоматический стенд сейчас не может навести прицел куда надо (S6 красный по
причине стенда), поэтому движение в воде лучше проверять ручным клиентом
(`tools\testclient\client.bat`) с записью mcproxy.

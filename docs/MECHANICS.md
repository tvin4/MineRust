# MECHANICS.md — реестр механик сервера

Назначение: одна таблица, по которой видно, что уже работает на нашем сервере,
что в работе и что не начато, откуда взяты байты и что именно осталось
неустановленным. Реестр обновляется по мере закрытия пунктов.

**Правило источников (AGENTS.md):** байты и поведение берём из трейсов и данных
генератора (`E:\MineRust-data\reports\*`), не из декомпилированного кода.
Строка «не установлено» означает: подтверждённого трейса/теста нет, механику
нельзя реализовывать «по памяти».

**Статусы:** `сделано` — есть проверка (трейс/юнит-тест/live), `в работе` —
начато и не закрыто, `не начато` — кода нет.

Планы: ломание блока — `docs/BLOCK-BREAKING.md`, плавание — `docs/SWIMMING.md`.

## Общие ограничения серверной части (на 15.11.2026)

- **Путь изменения блока есть, но только в памяти.** Шаг 13a добавил
  `net::store::ChunkStore` (снимок провода + `BlockStates`), шаг 13b —
  `set_block` из `player_action`: изменённый чанк пересобирается, остальные
  чанки остаются теми же `Arc`. На диск ничего не пишется, кеш живёт до
  перезапуска сервера.
- **Кеш чанков — `Arc<ChunkStore>` с инвалидацией по чанку.** Снимок
  `ReadyChunks` публикуется через один `RwLock<Arc<..>>`; вход (и каждая
  под-порция) берёт `snapshot()`, поэтому вошедший позже видит изменённый блок
  (`crates/net/src/store.rs`, `docs/DECISIONS.md` «Шаг 13a/13b»).
- **Движка света нет** (см. п. 7).
- **`blocks.json` не содержит твёрдости:** полей `hardness`/`resistance` в отчёте
  нет (1286 состояний, только `id`/`property`/`states`). Источник твёрдости и
  времени копания — не установлен; нужен ответ владельца (см. вопросы в
  `docs/BLOCK-BREAKING.md`).
- **Реестр блоков:** `E:\MineRust-data\reports\registries.json` (реестр
  `minecraft:block`, имя → protocol_id).
- **Планируемый этап:** `ARCHITECTURE.md` — M5 «блоки + свет (+ чат/команды)».

## Журнал изменений

- **16.11.2026, шаг 13c.** Записаны ванильные трейсы S8 (вода) и S9 (creative-
  ломание) автоматическими сценариями стенда. S8: поза SWIMMING (3), флаги
  `0x10`/`0x18`, air supply (index 1, 299→201, регенерация), `oxygen_bonus`
  при погружении; `water_movement_efficiency` не отправляется; звук входа/
  выхода из воды отсутствует. S9: creative = `player_action 0x00` на каждый
  блок → сразу `block_update` + ack (`0x03` не шлётся); наблюдателю —
  `level_event` 2001 (data = state id блока) + `swing_animation`;
  `block_destruction`/`sound` нет. Тап attack не даёт пакетов даже на ванили.
- **15.11.2026, шаг 13b.** Ломание блока в survival: разбор serverbound
  `player_action` (41) и серверное подтверждение по байтам S3. Финиш меняет
  блок в `ChunkStore`, `block_update` уходит всем (копающему тоже), затем
  `block_changed_ack` с эхом sequence. Отказ — гипотеза. Не реализованы:
  трещины (`block_destruction`), звук (`level_event`), предмет, свет.
- **15.11.2026, шаг 12.** Реестр заведён; статусы A/B/C подтверждены ручной
  проверкой владельца (два клиента, survival): углы при входе, присед, присед
  при входе к приседающему, спринт (с частицами), взмах в воздух и при ломании.
  D (плавание/ползание) и ломание блока — не реализованы.

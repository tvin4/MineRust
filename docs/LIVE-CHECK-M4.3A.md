# Live check — M4.3 часть A (пул регионов; поведение не должно измениться)

Состояние: **не выполнялось владельцем**. Живой сервер идёт через
`net::serve_with` с пулом `workers = ядра−2`, но регион один, поэтому тик
и inline, и пул простаивает: критерий — вход и ходьба **как в M4.2**.
Автоматически: `cargo test --workspace` (K=0/1/4 равный `TickOutcome`,
порядок merge, остановка пула, 1000 пустых тактов K=4) и e2e-смоук с
ручным `parity::Client` из прошлого раунда.

## Шаги (5 строк, коротко)

1. Запустить `tools\run-server.bat` (`workers` по умолчанию в `server.toml`
   можно не указывать); ждать `listening`, без `WARN`/`ERROR`.
2. Войти клиентом 26.3 на `localhost:25565` (view distance 8) — экран
   входа и 289 чанков приходят как раньше, без «дыр» и зависаний.
3. В `F3` пройти 30+ блоков вперёд/назад: координаты идут плавно, без
   скачков и откатов (тот же чек, что в M4.2).
4. В логе сервера не должно быть строк `tick woke late` при входе и ходьбе
   (если есть — записать `late_ms`, тик и число игроков).
5. Скриншот (мир + F3) и, если была строка `tick woke late`, её текст —
   в отчёт; также записать `workers` из `server.toml`.

## Заметки

- `workers = 0` в `server.toml` возвращает ровно поведение M4.2 (пула нет);
  сравнение «0 vs default» — по логу и ощущениям, цифры не обязательны.
- Опоздание тика при входе из живого лога M4.2 (261 мс) на in-process
  сервере не воспроизвелось (`C:\MineRust-data\traces\m43-jitter.md`); если
  оно есть и сейчас — строка `tick woke late` его покажет.
